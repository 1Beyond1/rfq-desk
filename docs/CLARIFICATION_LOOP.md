# 本地澄清往返

这是本地离线规则与人工审阅流程，没有邮件客户端或自动外发。任意自然语言不会被冒称已理解。

1. 在项目根目录运行 `python distribution/serve.py` 启动本地服务，浏览器访问 `http://127.0.0.1:5311/`（离线模式下不发送外部模型请求）。
2. 从文件选择器导入 `data/synthetic/clarification/roundtrip.eml`。009401/009402 同件号，分别缺单位/件状，不能按件号合并。
3. 点“登记当前澄清项”。每项保留稳定行、RFQ/件号、字段、问题、开始工作/行版本、原值/出处。再次登记不重复创建未决项。价源不足在核价处理。
4. “导出澄清草稿 TXT”下载含问题编号和当前行版本的文本；不发送、不解决。可人工在外部处理，本系统不证明邮件已发出。
5. 在澄清区追加答复原件，再从具体问题点“关联本地答复”，选择文件、答复针对的行版本、核对人和依据。只认当前工作单已追加的原件；禁止同名覆盖、重复 hash 登记。旧版本只留记录。
6. “生成离线标签候选”只识别明确冒号标签（如 RFQ No.、Part Number、Unit、Condition、Quantity）。从对应问题的答复候选按钮进入，原文/位置可查；锁定局部修订及稳定行，只更新本项字段，其余继承。核对字段值、RFQ/件号、出处后填写人/理由并确认归属。无本次目标字段、错目标、旧版或原件变化都拒绝。
7. 可以只采用不关闭；“已核对实际字段变化，并同时解决”需明确勾选，且实际改变字段、该项业务异常消除，否则整次事务不写。`insufficient.txt`未提供单位，不能解决问题。`reply-unit.txt`只解决009401；009402仍阻断。再以`reply-condition.txt`解决009402。
8. 没有可用候选时点“定位原行/人工裁定”，先保存字段及明确依据，再点“核实人工裁定并解决”，留下独立核对记录。只改问题状态不能跳过无效/缺字段。人工路径保留原文和人工台账，不能补假引用。
9. 已解决字段或归属变化使结论过期，保留先前记录。稳定行重新归属时，原问题不可猜映射：人工核实后明确结束旧目标项，当前新归属的异常仍阻断，可再登记新问题。结束旧目标不表示回答了旧问题。
10. 核价可显式录入合成卡 `SYN-CLARIFY-CARD`：件号CLARIFY-001、EA/FN、USD12.35、2026-01-01至2030-12-31、合成交期7天。当前两行2/3，总额61.75。全部问题解决且价源有效后批准、下载CSV/HTML。改价13.00使旧批准失效，重批后65.00。仅为合成工程验收。

状态分为待答复、收到待核对、已解决、结论/目标过期及旧目标明确结束。未决项阻止当前有效行批准及正式输出；价格变更、来源核验、乐观锁409和当前版本输出守卫沿用原逻辑。草稿/历史下载是快照，不能远程收回。

系统无法仅凭文件名或自然语言证明作者回复的真实时序。目标行版本由人工明确声明，候选采用时再次校验；旧资料不得自动重基。原件和记录仅在本地，生产身份/签章/邮件投递不在此范围。
